# Interrupt '26 NY — role-aware docs assistant

A demo of **Managed Deep Agents (MDA)** built for the Interrupt '26 New York
talk.

One deployed agent answers documentation questions. You pick who is asking —
**Lang, an engineer** or **Polly, a non-technical employee** — and the same
question gets a different answer, because middleware gives the model a
different set of tools for each role.

| Role | Corpora the model can search |
|---|---|
| Lang · Engineer | internal engineering runbooks, public product docs |
| Polly · Employee | public product docs only |

Ask *"Do we require retry middleware on model calls?"*: Lang gets **"Yes,
required"** (from the runbooks), and Polly gets **"No, optional"** (from the
public docs). Ask *"What is our on-call escalation path?"*: Lang answers, and
Polly can't, because her model never receives a tool that can read the
runbooks.

> **The identity is simulated.** There is no login, authentication, or
> authorization. You choose a name from a menu and the server writes it into a
> cookie. What *is* real is that the server sets the role and the tool
> filtering is deterministic code, not a prompt. (The side-by-side view, on by
> default, lets the browser pick each pane's role from the two allowed ones;
> set `DEMO_COMPARE_MODE=false` to make the role cookie-only.)

The agent is **already deployed** in the shared Demo workspace. To run the demo
you only run the UI locally.

## Quick start: run the demo

You need **Node 20+**, **pnpm**, and a **LangSmith API key issued in the shared
Demo Workspace** (`a3866f07-2cf5-4e9c-a287-59ed817c2ecd`).

```bash
cd ui
cp .env.example .env.local     # paste your key into LANGSMITH_API_KEY (LangChain Demo Workspace)
pnpm install
pnpm dev                       # → http://localhost:3000
```

Then:

1. Open http://localhost:3000 and pick **Lang** or **Polly**.
2. Ask a question, or click a suggested one.
3. Switch identity and ask the same question again, or click **Side by side**
   in the top bar to see both at once.
4. Follow the trace link on any answer to see the run in LangSmith.

**Check your connection:** `curl localhost:3000/api/lg/info` should return
HTTP 200.

### Troubleshooting

- **403 from the deployment:** your key is from the wrong workspace. Two orgs
  each have a workspace called "Demo Workspace"; you need the one with the ID
  above, not `fd6b1198…`.
- **First answer is slow:** the deployment is cold. Ask one throwaway question
  before presenting.
- **Other people's runs in LangSmith:** everyone shares one deployment and one
  tracing project. Threads are per browser, so you only see your own
  conversations in the UI.

## Changing the agent

Skip this section unless you are changing the agent's behavior. It needs
Python 3.11+, [`uv`](https://docs.astral.sh/uv/), and write access to the Demo
workspace.

```bash
cd agent
cp .env.example .env           # LANGSMITH_API_KEY, LANGSMITH_WORKSPACE_ID
uv sync
uv run python -m pytest        # offline tests
uv run mda dev                 # local server
```

Deploying has a required order: version check, regenerate grants, deploy,
record the version, verify. See [agent/README.md](agent/README.md). Bump
`contracts/version.py` whenever answers could change. The current version is
shown in the UI and on every trace as `metadata.demo_version`.

To change the documents, see [corpus/README.md](corpus/README.md). Keep
`engineering/` fictional.
